# Obsidian Full-Stack Testing Walkthrough

This guide provides step-by-step instructions for running the Obsidian platform locally and testing the core user flows, including authentication, HR intelligence, and employee career management.

## 1. Running the Site

Ensure your local PostgreSQL database is running, then start the application. We have bundled a convenient script that starts both the backend API (port 3000) and the frontend Vite server (port 5173).

```bash
# In the root obsidian/ directory
npm install
npm run dev
```

The frontend will be available at: **http://localhost:5173**

---

## 2. Testing Authentication (Login)

The application features Role-Based Access Control (RBAC). You can test the platform from two distinct perspectives:

### Employee Login
1. Navigate to `http://localhost:5173/login`
2. Select **Employee Portal**
3. Use the seeded credentials:
   - **Email:** `alice@obsidian.test`
   - **Password:** `password123`
4. *Expected Result:* You are authenticated and redirected to the Employee Dashboard. The API caches your `userId` securely.

### HR Login
1. Navigate to `http://localhost:5173/login`
2. Select **HR / Admin Portal**
3. Use the seeded HR credentials (e.g., `admin@obsidian.local` with your database seed passwords).
4. *Expected Result:* You are authenticated as an HR Admin and redirected to the HR Intelligence Hub.

## 3. Testing Employee Pages

Once logged in as an Employee (Alice):

### Dashboard & Navigation
- **Dashboard:** Provides a high-level summary of active career goals and quick actions.
- **My Profile:** Click this in the sidebar. You will be routed to `/employees/<your-user-id>` (e.g., Alice's UUID) to view your specific skills, experience, and projects fetched from the backend.

### AI Role Matching
1. In the sidebar, click **Career Roadmap** or **Matches**.
2. *Expected Result:* The page fetches Alice's Role Matches from the backend.
3. *AI Integration:* The `explanation` field for each match is dynamically generated by the **Gemini AI SDK** (`gemini-3.8-flash`), explaining exactly why Alice is a strong candidate for the Senior Backend Engineer role based on her profile.

### Update Resume (Onboarding)
1. Click **Upload Resume** in the sidebar (routes to `/onboarding`).
2. *Expected Result:* You are presented with the resume parser UI. 
3. *Note:* The file upload parsing connects to the backend skill extraction logic (mocked visually in the frontend, pending backend parser pipeline).

## 4. Testing HR Pages

Once logged in as HR:

### HR Dashboard
- Routes to `/hr`. 
- *Expected Result:* Displays organization-wide metrics (e.g., retention risk, internal mobility, top skills in demand). *Note: Some charts utilize frontend mock placeholders while advanced analytics routes are developed.*

### Talent Directory
- Click **Talent Directory** in the sidebar.
- *Expected Result:* The page successfully fetches and renders all employees from the `/api/v1/employees` endpoint.
- *Pagination Fix:* The infinite loading spinner bug has been resolved. The backend safely defaults to `page=1, limit=50` and returns the seeded database users.

### Employee Drilldown
1. From the Talent Directory, click on any employee card (e.g., Alice).
2. *Expected Result:* As HR, you bypass the IDOR (Insecure Direct Object Reference) protection. The backend allows you to view the full profile and skill breakdown of the selected employee.
